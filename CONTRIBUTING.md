# Cómo contribuir

Utiliza las plantillas de incidencias para errores reproducibles o propuestas y los pull requests para cambios de código. Explica el problema y el comportamiento final esperado, con datos ficticios y versiones de WordPress, WooCommerce, PHP y del plugin.

Lee [desarrollo y pruebas](docs/development.md), ejecuta las comprobaciones aplicables y documenta sus límites. Los cambios de credenciales, importes, política 3DS, correlación, concurrencia o resultados inciertos necesitan regresiones. Conserva los mínimos PHP 7.4 y WooCommerce 9.0, o justifica y verifica cualquier cambio de requisitos.

No incluyas credenciales reales, tarjetas, respuestas bancarias, documentos privados, datos de compradores ni capturas operativas. Los fixtures son ficticios y las pruebas no realizan cobros. Las vulnerabilidades se reportan por el canal privado de [seguridad](SECURITY.md).

El README y las guías operativas se mantienen en español. `readme.txt` conserva la ficha fuente en inglés preparada para el directorio, igual que el proyecto LAFISE. No presentes simulaciones como pruebas bancarias ni anticipes una aprobación del directorio.
